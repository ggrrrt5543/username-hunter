# Разработка

Python 3.10+.

```bash
python -m venv .venv
# Linux/macOS: . .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/build_release.py
```

В Pull Request опиши изменение и добавь тест. Не добавляй реальные Telegram-сессии, `.env` или пользовательскую базу.

## Как выпустить обновление

1. Измени код и добавь тесты.
2. Подними `VERSION` в формате `X.Y.Z` (например, `8.4.1`).
3. Обнови `CHANGELOG.md` и `docs/release-notes.md`.
4. Отправь коммит в `main`.
5. GitHub Actions выполнит офлайн-тесты на трёх ОС и опубликует новый Release с ZIP и контрольной суммой.

Повторный push с прежним VERSION не заменяет существующий релиз. Ветка `main` может содержать изменения, ещё не вошедшие в последнюю выпущенную версию. Release всегда указывает на конкретный проверенный коммит.

Автосборка не означает, что GitHub самостоятельно пишет обновления: новый код сначала должен быть отправлен в репозиторий.
